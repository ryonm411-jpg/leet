Python rules that trip people up

Taught in Lesson 13 · Each rule here is one you've missed in a lesson · Terms in the glossary

RuleRightWrong
range takes whole numbers and stops before the end (docs) range(3) → 0, 1, 2
range(2, 5) → 2, 3, 4
range(len(nums)) → every index		 range(nums) raises TypeError, because a list isn't a number
A function returns None unless it reaches a return (docs) return w * h Leaving w * h as the last line. Python works it out, then throws it away. Ruby would return it, but Python doesn't
A variable named after a built-in hides it inside that function (docs) best = 0, total = 0, low = 0 max = 0 and then max(a, b) raises TypeError: 'int' object is not callable
Python spells it elif (docs) elif x > 0: elsif (Ruby) and else if (JavaScript, C) are SyntaxErrors
Code after a loop runs once, when the loop finishes Check the best value once more after the loop, or on every step Updating best only when a streak breaks. A streak that runs to the last day is never counted

Read before your first Run

  1. Every ( and [ is closed on the same line.
  2. Every def, if, elif, else, for and while line ends with :.
  3. No variable is called max, min, sum, list, dict or id.
  4. There's a return after the loop, and it returns the right thing when the answer is at the very end.
