When to reach for it

The input is sorted (or partly sorted), or the problem asks for O(log n). Also when the answers are sorted: "the biggest k where k × k ≤ x" can be searched over k, even with no list.

Template: find the target

def search(nums, target):
    lo, hi = 0, len(nums) - 1
    while lo <= hi:                 # one item left still gets checked
        mid = (lo + hi) // 2        # // gives an int index
        if nums[mid] == target:
            return mid
        elif nums[mid] < target:
            lo = mid + 1            # answer is right of mid
        else:
            hi = mid - 1            # answer is left of mid
    return -1                       # here lo is the insertion point

Time O(log n): a million items take about 20 checks. Space O(1).

Variants

Problem asks forChange
Where target would be inserted (LeetCode 35)Return lo instead of -1. Python's bisect.bisect_left does the same.
Biggest value that still passes a test (Sqrt(x))Search over possible answers. When mid passes, save it and go right with lo = mid + 1.

Traps

TrapFix
while lo < hi skips the last item, so [5], 5 gives -1Use lo <= hi with this template.
lo = mid or hi = mid can loop foreverMove past mid: mid + 1, mid - 1.
(lo + hi) / 2 is a float, so indexing raises TypeErrorUse //.
hi = len(nums) reads past the endhi = len(nums) - 1, the last index.
Using it on unsorted inputCheck that it's sorted first. If not, it's probably a hash map.
