The four steps (you lead the conversation)

  1. Use cases, constraints, assumptions. Ask before drawing: what must it do, for whom, and how much traffic? Say what's out of scope.
  2. High-level design. Client, server(s), database: boxes and arrows.
  3. Core components. Zoom into the one part that makes this system special.
  4. Scale. Find the bottleneck, fix it, name the trade-off, and repeat.

Worked example: link shortener

  • Scope: shorten, expand, expiry, analytics. Out of scope: login, editing, custom codes.
  • Numbers: 10M writes and 100M reads a month, which is about 4 and 40 a second, 10:1 read-heavy.
  • Core: a code → URL key-value lookup. The code is 7 Base 62 characters (627 options), from a hash with a clash check, or from a counter (no clashes, but guessable).
  • Scale: cache hot links, with read replicas for misses. Writes at 4 a second fit one primary database.
