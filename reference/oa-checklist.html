Rules, from your invitation

  • No outside resources. You acknowledge that you'll complete it "without external assistance or resources", with no personal IDEs. Amazon's public page mentions public docs, but your invitation is stricter, so plan on no docs at all. Know your Python by heart.
  • Single monitor. Full-screen IDE. Latest Chrome or Edge. Stable internet.
  • A photo of you holding a photo ID (a student ID is fine) before you start. Your webcam stays uncovered, and your screen and webcam are recorded.
  • Don't refresh the page over and over. If something breaks, log out and back in with the link, then contact your recruiter.
  • From Amazon's public page: don't use Print Screen, because the session is terminated. Don't paste in code from outside.

What they grade (Amazon's video)

Reading the problem deeply, turning the idea into code accurately, choosing the right data structure (list, map or set), common-sense runtime complexity, and a simple solution. They say they don't set trick questions.

Coding problem

StepDo
1Read it one paragraph at a time, as Amazon's video does, and list every requirement. Use the example to decode the output format. Write two examples, including an edge case: one item, all equal, or the answer at the very end.
2Name the pattern: seen map, frequency count, two pointers or sliding window. If none fits, say the brute force.
3If no faster idea comes within about 10 minutes, code the brute force. A working answer beats an unfinished one.
4Trace one example by hand, then run.
5With time left, make it faster. Keep the working version in a comment.

Repository question

  1. Read the task and the README. Know what "done" means.
  2. Run the tests before changing anything.
  3. Read the failing test. It gives you the input, the expected result and what actually happened.
  4. Follow the calls with F12, Go to Definition. The bug is where a value first goes wrong, which is often not in the file the test names.
  5. Set a breakpoint, Debug Test, and look at the real values.
  6. Make the smallest change, then run every test. Never edit a test to make it pass.

The IDE includes an AI coding assistant. Treat its suggestions like a teammate's code: read them, make sure you understand them, and confirm them by running the tests. You still own the result.

Work Simulation and Work Style

The Work Simulation gives you SDE scenarios and decisions. Reason from the customer outward, and weigh speed against quality the way the Leadership Principles do. The Work Style surveys explore how you approach work and make decisions. Third-party guides say it uses pairs of statements, which is unconfirmed. Answer honestly and consistently. Guessing what Amazon "wants" tends to make your answers contradict each other.
