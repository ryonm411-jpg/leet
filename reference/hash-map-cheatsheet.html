When to reach for one

You keep searching for a value you may already have passed. Spend O(n) memory to make each lookup O(1) on average.

The seen-map pattern

def two_sum(nums, target):
    seen = {}  # number -> its index
    for i, x in enumerate(nums):
        complement = target - x
        if complement in seen:      # check first
            return [seen[complement], i]
        seen[x] = i                 # then store

Check before you store, so an element can't pair with itself. Time O(n), space O(n).

The frequency-count pattern

def can_construct(ransom_note, magazine):
    counts = {}  # letter -> how many are left
    for c in magazine:
        counts[c] = counts.get(c, 0) + 1
    for c in ransom_note:
        if counts.get(c, 0) == 0:
            return False
        counts[c] -= 1
    return True

Use it when "how many" matters, not just "is it present". d.get(key, 0) treats a missing key as 0, while d[key] raises a KeyError. Time O(n + m). Space O(1) here, because there are only 26 letters. A dict's space is the number of distinct keys it can hold, so counting arbitrary words would be O(n).

d.get(k, 0) += 1 is a SyntaxError. Write d[k] = d.get(k, 0) + 1.

Working out a dict's space

  1. What is one key?
  2. How many different keys are possible?
  3. Does that number grow with the input? A fixed limit means O(1). No limit means O(n).

One letter: at most 26 keys, so O(1). A whole word or a number: all n could differ, so O(n).
