Working in someone else's code

About 45 minutes · Your win: fix a bug and ship a feature in a project you didn't write, using its tests and a debugger

The OA's code repository question is a real-world task across several files, in a VS Code-style editor with Run and Debug. That's different from LeetCode. The skill isn't inventing an algorithm. It's finding your way around code you didn't write without breaking it. Today you do exactly that in real VS Code.

The method

On an unfamiliar codebase, work in this order. Each step narrows where you look.

  1. Read the task, then the README. Know what "done" means before you touch anything.
  2. Run the tests before changing anything. Now you know what already fails, so you won't blame yourself for it later.
  3. Read the failing test. It's the most precise description of the bug you'll get: the input, the expected output, and what actually happened.
  4. Follow the call. Start in the function the test calls, and jump to each function it calls in turn. In VS Code, F12 (Go to Definition) jumps there.
  5. Stop it mid-run with a breakpoint instead of guessing. Look at the real values.
  6. Make the smallest change that fixes it, then run every test, not only the one you were fixing.

Set up (about 5 minutes)

  1. In VS Code, install the Python extension from Microsoft. It adds the Testing panel and the debugger. You don't have it yet. VS Code's Python quick start shows how.
  2. Open the folder Downloads\Leet\practice-repos\0011-warehouse with File → Open Folder.
  3. Open the terminal with Ctrl+` and run py -m unittest -v from the 0011-warehouse folder itself, not from tests. Otherwise Python can't find the warehouse package and every test fails with ModuleNotFoundError. You should see 14 tests, with 4 failing. That's your starting point.

The tasks

Start the timer, then open TASK.md in the project. Two tickets: a bug and a feature. Don't edit any test.

Ticket 1: the bug

  1. Find the failing test for it in tests/test_orders.py. What does it set up, and what does it expect?
  2. Open warehouse/orders.py. Put your cursor on each function that fulfil calls and press F12 to follow it.
  3. Set a breakpoint by clicking left of the line number on the line you suspect. Then, in the Testing panel (the flask icon), right-click that one test and choose Debug Test. When it stops, hover over the variables and read their values. The VS Code testing docs cover this.
  4. Fix it with the smallest change you can, then run all the tests again.
