OA rehearsal: two problems, 70 minutes

About 85 minutes in total · Your win: both problems submitted before one 70-minute clock runs out, using Amazon's own way of breaking a problem down

Amazon's prep course says the intern coding assessment takes about 70 minutes on average, and its course page mentions two coding problems (Amazon: OA prep for SDE roles). Your recruiter email described a different shape: one coding problem, then a repository task. The invitation email decides which one is yours. Two problems in 70 minutes is the tighter of the two, so that's what this rehearsal practises.

What Amazon says it's grading

From the transcript of Amazon's video "What is Amazon Assessing?", five things:

Amazon's wordsWhat it means for you
Problem statement retentionRead it deeply. Every rule in the statement is a hidden test.
Coding abilityTurn the idea into code accurately. This is where your runs go.
Data structure applicationKnow when to use a list, a map (dict) or a set. That's exactly your pattern work.
Runtime complexity"Common-sense" complexity: walk through your own code and say what it costs.
Create a simple solution"We really value the simple solution." Clear names and no clever tricks.

The same video says they aren't testing tricky questions or deep knowledge of one language. So Python you know well beats anything fancy.

How Amazon breaks a problem down

In "How to break down the coding problem", the engineer reads the statement one paragraph at a time and stops after each to say what they learned. They list every requirement they find ("alphabetical order, case insensitive, wait until two characters"). When the output format is confusing, they work it out from the example. They also notice things the statement doesn't say: "the input is not ordered".

Problem A below is the problem from that video, so you'll practise exactly that method on it.

Rules for this rehearsal

  • One 70-minute clock for both problems. Start it, and don't stop it until you're done or it runs out.
  • Do the breakdown questions first. They're part of the 70 minutes, as reading is in the real thing.
  • If you're stuck on one problem, move to the other and come back. Amazon's own advice says the same.
  • Before each first Run, read through the four-point list, then trace the example by hand.
  • No hints are given. On the day, the Python docs are allowed (see the OA checklist), so string methods and sorting are fair game here too.

Problem A: Customer review suggestions

From Amazon's breakdown video, written up here from its transcript. Inputs and edge cases are pinned down below so the tests are fair.

Amazon wants to suggest search keywords while a customer types into the review search box. Once the customer has typed at least two characters, the system suggests at most three keywords from repository that start with what's been typed so far. If more than three match, return the first three in alphabetical order. Compare case-insensitively, and return every suggestion in lowercase.

repository is a list of unique words, in no particular order. query is the customer's full search, typed one character at a time. Return a list of lists: one list of suggestions for each prefix of length 2, 3, …, up to len(query). A prefix with no matches gets an empty list. If the query is shorter than 2 characters, return [].

Example: repository = ["mobile", "mouse", "moneypot", "monitor", "mousepad"], query = "mouse" gives

[["mobile", "moneypot", "monitor"],   # "mo"
 ["mouse", "mousepad"],               # "mou"
 ["mouse", "mousepad"],               # "mous"
 ["mouse", "mousepad"]]               # "mouse"

Breakdown: which of these is not a requirement of the problem?

For query = "mouse", how many inner lists should you return?

You sort the lowercased repository once (n words), then, for each of the q prefixes, scan every word with startswith. Roughly what's the time cost, treating word length as small?

Problem B: Warehouse restock

A warehouse starts the week with start units of a product. changes[i] is the net change on day i: positive for deliveries and negative for orders shipped. After every day, the stock must be at least 1. Return the smallest whole-number start (at least 1) that keeps it that way. len(changes) ≥ 1.

Example: [-3, 2, -3, 4, 2] gives 5. Starting with 5, the stock goes 2, 4, 1, 5, 7, and never drops below 1. Starting with 4, it would hit 0 on day 3.
