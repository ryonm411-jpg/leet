What a stack is

A stack is a pile you only touch at the top: the last thing in is the first thing out (LIFO). Python has no separate stack type. A plain list is the stack, as the Python tutorial shows: "To add an item to the top of the stack, use append()", and to take it back, "use pop() without an explicit index". Both are O(1).

Problem 1: Remove All Adjacent Duplicates In String

LeetCode 1047, Easy. Statement written from memory, as LeetCode blocks automated reading.

Given a lowercase string s, repeatedly remove two equal letters that sit next to each other, until none are left. Return the final string. The answer is unique.

Examples: "abbaca" gives "ca": removing bb leaves "aaca", then removing aa leaves "ca". "azxxzy" gives "ay".

Think: when a new letter arrives, which letter could it cancel? Only the one just before it that's still standing.

Stuck for 6 minutes? Show a hint

Loop over each c. If the stack isn't empty and its top equals c, pop (they cancel). Otherwise push c. At the end, return "".join(stack). The if stack check comes first, so stack[-1] never runs on an empty stack.

Problem 2: Valid Parentheses

LeetCode 20, Easy. Statement written from memory.

Given a string s made only of ()[]{}, return True if it's valid: every opener is closed by the same type of bracket, closers come in the right order, and every closer has a matching opener. s has at least 1 character.

Examples: "()" True. "()[]{}" True. "(]" False. "([)]" False. "{[]}" True.

You push openers onto the stack. When you reach a closer c, you want the opener it needs in one lookup. Which dict?

That pairs dict, with its 3 entries. How much space does it use as s gets longer?

Stuck for 8 minutes? Show a hint

For each c: if it's an opener, push it. If it's a closer, there are two ways to fail. Either the stack is empty (nothing to close), or stack.pop() != pairs[c] (wrong type). Either way, return False. After the loop, the string is valid only if nothing is left open: return not stack. Trace "]" and "((" before you run.

Before the bonus: a stack that stays sorted

Problem 3 asks, for each day, how long until a warmer one. The trick is a monotonic stack: a stack of the days still waiting for a warmer day. They're always coolest on top. When a warm day arrives, it answers every waiting day it beats. Pop them, then push itself. The stack holds indices, because the answer is a distance in days. Step through it with temperatures [70, 68, 71, 69, 72]:

Each day is pushed once and popped at most once, so the whole thing is O(n) time, even with a loop inside a loop. Checking every later day for every day would be O(n²).

Bonus, Problem 3: Daily Temperatures

LeetCode 739, Medium. Statement written from memory.

Given a list temperatures, return a list answer where answer[i] is how many days you wait after day i for a strictly warmer day. If there isn't one, it's 0.

Examples: [73, 74, 75, 71, 69, 72, 76, 73] gives [1, 1, 4, 2, 1, 1, 0, 0]. [30, 40, 50, 60] gives [1, 1, 1, 0].

Stuck for 10 minutes? Show a hint

Start with answer = [0] * len(temperatures) and stack = []. For each i, t in enumerate(temperatures): while stack and temperatures[stack[-1]] < t: pop j and set answer[j] = i - j. After the while loop, push i. Days still on the stack at the end keep their 0. Use <, not <=, because an equal day isn't warmer.
