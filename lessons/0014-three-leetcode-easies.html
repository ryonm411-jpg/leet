Which pattern? A note on "i < j"

In Lesson 13 you picked two pointers twice, both on problems saying "positions i < j", but your code then used the right pattern. "i < j" only means "a pair, in order". Two pointers needs one more clue: the input is sorted, or you're walking two sequences side by side.

Unsorted list. Is there a pair i < j with nums[i] == nums[j]? Best approach?

Problem 1: Find Pivot Index

LeetCode 724, Easy. The statement is paraphrased, because LeetCode blocks automated reading. Check the exact wording on LeetCode.

Return the leftmost index i where the sum of everything to the left of i equals the sum of everything to the right of i. The element at i belongs to neither side. At index 0 the left sum is 0. If there's no such index, return -1. Numbers can be negative.

Example: [1, 7, 3, 6, 5, 6] gives 3: 1 + 7 + 3 = 11 and 5 + 6 = 11.

Which approach fits best?

Stuck for 10 minutes? Show a hint

Work out total = sum(nums) once, before the loop. Keep left, starting at 0. At each index, the right side is total - left - nums[i]. Compare, then add nums[i] to left, in that order.

Problem 2: Is Subsequence

LeetCode 392, Easy. Paraphrased. Check the exact wording on LeetCode.

Given strings s and t, return True if s is a subsequence of t. That means you can delete some characters of t, or none, without reordering the rest, and get s.

Example: s = "abc", t = "ahbgdc" gives True. s = "axc" with the same t gives False.

Which approach fits best?

Stuck for 10 minutes? Show a hint

Keep i, the index of the next letter of s you still need. Loop over every character of t. When it matches s[i], move i on. Guard i < len(s) before reading s[i]. At the end, did i reach len(s)?

Problem 3: Majority Element

LeetCode 169, Easy. Paraphrased. Check the exact wording on LeetCode.

Return the element that appears more than n / 2 times in nums, where n is the length. You can assume it always exists.

Example: [2, 2, 1, 1, 1, 2, 2] gives 2.

Which approach fits best?

Stuck for 10 minutes? Show a hint

Count with counts[n] = counts.get(n, 0) + 1, then return the key whose count is greater than len(nums) // 2. Don't call nums.count(x) inside a loop, because that's O(n²) and fails the big hidden test.
