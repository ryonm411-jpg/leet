Problem 1: Isomorphic Strings

LeetCode 205, Easy. The statement is paraphrased, because LeetCode blocks automated reading. Check the exact wording on LeetCode.

Strings s and t have the same length. Return True if you can replace characters in s to get t, where every copy of a character is replaced by the same character, and no two different characters may map to the same character. A character may map to itself.

Examples: "egg", "add" gives True (e→a, g→d). "foo", "bar" gives False, because o would need to become both a and r.

Which approach fits best?

Stuck for 10 minutes? Show a hint

Loop with for a, b in zip(s, t):. Keep s_to_t and t_to_s. If a is already in s_to_t and maps to something other than b, return False. Do the same check for b in t_to_s. Otherwise store both. One dict alone passes the examples but fails "badc", "baba".

LeetCode says the strings hold ASCII characters, which has 128 possible characters. How much extra space do your dicts use as the strings get longer?

Problem 2: Squares of a Sorted Array

LeetCode 977, Easy. Paraphrased. Check the exact wording on LeetCode.

nums is sorted from smallest to largest and may contain negatives. Return a new list of the squares of each number, also sorted from smallest to largest.

Example: [-4, -1, 0, 3, 10] gives [0, 1, 9, 16, 100].

LeetCode's follow-up asks for O(n) time. Which approach gets that?

Stuck for 10 minutes? Show a hint

Make result = [0] * len(nums) and set pos = len(nums) - 1, the slot to fill next. With left = 0 and right = len(nums) - 1, loop while left <= right: whichever of nums[left] ** 2 and nums[right] ** 2 is bigger goes into result[pos], then that pointer moves inward and pos goes down by 1. If you're short on time, sorted(n * n for n in nums) is a safe answer to bank first.

Problem 3: Maximum Subarray

LeetCode 53, Medium. Paraphrased. Check the exact wording on LeetCode.

Return the largest sum of any non-empty run of neighbouring numbers in nums. Numbers can be negative, and the run must contain at least one number.

Example: [-2, 1, -3, 4, -1, 2, 1, -5, 4] gives 6, from [4, -1, 2, 1].

Which approach fits best?

Stuck for 10 minutes? Show a hint

Start current = nums[0] and best = nums[0], not 0, or an all-negative list goes wrong. Loop over the rest with range(1, len(nums)). Each step: current = max(nums[i], current + nums[i]), then best = max(best, current). Don't name either variable max.

Bonus, Problem 4: Top K Frequent Elements

LeetCode 347, Medium. Paraphrased. Check the exact wording on LeetCode.

Return the k numbers that appear most often in nums, in any order. The answer is always unique, so there are no ties to break at the cutoff.

Example: [1, 1, 1, 2, 2, 3], k = 2 gives [1, 2].

Which approach fits best?

Stuck for 10 minutes? Show a hint

Count with counts[n] = counts.get(n, 0) + 1. Then sorted(counts, key=counts.get, reverse=True) gives the keys from most to least frequent, and [:k] takes the first k. That's O(n log n), which LeetCode accepts. Don't call nums.count(x) in a loop: that's O(n²).
