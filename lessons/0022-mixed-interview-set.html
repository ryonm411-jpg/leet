Four problems, and nobody tells you the pattern

In an interview, the problem doesn't come with a chapter title. Each problem here uses a pattern you've already met, but they're mixed up on purpose. Mixing makes practice feel harder, and it's the kind of difficulty that sticks. Before each problem you'll name its pattern, then code it. Your first run is your interview answer, as in a live interview, where you can't run code at all. A short checklist of the slips that cost you the most runs in Lesson 21 unlocks that first run. Problem 1: Longest Palindrome

LeetCode 409, Easy. Statement written from memory, as LeetCode blocks automated reading.

Given a string s of uppercase and lowercase letters, return the length of the longest palindrome you can build from those letters. You can rearrange them and don't have to use them all. Case matters: "Aa" isn't a palindrome.

Examples: "abccccdd" gives 7 (one is "dccaccd"). "a" gives 1.

Which pattern fits best?

Your count dict is keyed by the letters of s. How much space does it use as s gets longer?

Stuck for 6 minutes? Show a hint

Count each letter. Every count gives count // 2 * 2 letters, using pairs only. If any count is odd, one leftover letter can go in the middle, so add 1, but only once in total. For "abccccdd": c gives 4, d gives 2, and a and b give 0 each. That's 6, plus 1 for the middle, so 7.

Problem 2: Move Zeroes

LeetCode 283, Easy. Statement written from memory.

Given a list nums, move every 0 to the end, keeping the non-zero numbers in their original order. Do it in place, changing nums itself with O(1) extra space and no new list. LeetCode's version returns nothing. Here, end with return nums so the tests can see it.

Examples: [0, 1, 0, 3, 12] gives [1, 3, 12, 0, 0]. [0] gives [0].

Which pattern fits best?

Stuck for 6 minutes? Show a hint

Keep write = 0, the spot for the next non-zero. Loop for read in range(len(nums)). When nums[read] != 0, swap: nums[write], nums[read] = nums[read], nums[write], then write += 1. The swap carries the zeros backwards for free. Trace [0, 1, 0, 3, 12] and write write, read and the list on each line.

Problem 3: Product of Array Except Self

LeetCode 238, Medium. Statement written from memory.

Given a list nums (length 2 or more), return a list answer where answer[i] is the product of every number except nums[i]. You may not use division, and it must run in O(n) time.

Examples: [1, 2, 3, 4] gives [24, 12, 8, 6]. [-1, 1, 0, -3, 3] gives [0, 0, 9, 0, 0].

Which pattern fits best?

Stuck for 10 minutes? Show a hint

answer = [1] * len(nums). Left pass: left = 1. For each i from the left, set answer[i] = left, then left *= nums[i]. The order matters, because answer[i] must not include nums[i]. Right pass: right = 1. For i from the right (warm-up's range), answer[i] *= right, then right *= nums[i]. For [1, 2, 3, 4], the left pass gives [1, 1, 2, 6].

Problem 4: Minimum Size Subarray Sum

LeetCode 209, Medium. Statement written from memory.

Given a list of positive integers nums and a positive int target, return the length of the shortest block of neighbours (a subarray) whose sum is at least target. If there isn't one, return 0.

Examples: 7, [2, 3, 1, 2, 4, 3] gives 2 (the block [4, 3]). 4, [1, 4, 4] gives 1. 11, [1, 1, 1, 1, 1, 1, 1, 1] gives 0.

Which pattern fits best?

Stuck for 10 minutes? Show a hint

left = 0, total = 0, best = len(nums) + 1 (bigger than any real answer). For each right, add nums[right] to the total. Then while total >= target: record right - left + 1 if it's smaller, take nums[left] out of the total, and move left one step. At the end, return 0 if best never changed, otherwise best.
