Part 3: binary search

If a list is sorted, you don't have to look at every item. Check the middle one. If it's too small, the answer can only be to its right, so throw the left half away. If it's too big, throw the right half away. Every check halves what's left. The Tech Interview Handbook puts it as a question to ask yourself: "Is the array sorted or partially sorted? If it is, some form of binary search should be possible" (Handbook, arrays). Its table gives search on a sorted array as O(log(n)).

You keep two indices, lo and hi, for the part of the list that could still hold the answer. Step through searching for 9, then for 2, which isn't there.

Look at the last step of the search for 2: when it gives up, lo is 2, which is exactly where 2 would go to keep the list sorted. Python's own bisect module is built on this: bisect_left will "Locate the insertion point for x in a to maintain sorted order". You'll use that fact in Problem 2.

The middle number is smaller than the target. Which line comes next?

Someone writes while lo < hi: instead of while lo <= hi:. With nums = [5] and target 5, what does their search return?

A sorted list has 1,000,000 numbers. At most how many middles does binary search check?

Problem 1: Binary Search

LeetCode 704, Easy. Statement written from memory, as LeetCode blocks automated reading.

Given a list nums sorted in ascending order with no repeats, and an int target, return the index of target, or -1 if it isn't there. It must run in O(log n) time.

Examples: [-1, 0, 3, 5, 9, 12], 9 gives 4. [-1, 0, 3, 5, 9, 12], 2 gives -1.

Stuck for 6 minutes? Show a hint

Start with lo = 0 and hi = len(nums) - 1. Loop while lo <= hi. Work out mid with //. Three cases: found it, so return mid. Too small, so lo = mid + 1. Too big, so hi = mid - 1. After the loop, return -1.

Problem 3: Valid Parentheses, cold

LeetCode 20, Easy. You met it in Lesson 21, where it took 6 runs and the hint. Don't reopen that page. This is the spaced retry: same problem, from a blank editor, two days later.

Given a string s of only ()[]{}, return True if every bracket is closed by the same type, in the right order, and every closer has an opener. Otherwise return False.

Examples: "()[]{}" gives True. "(]" gives False. "([])" gives True.

Which pattern fits best?

Stuck for 8 minutes? Show a hint

A dict from closer to opener: {")": "(", "]": "[", "}": "{"}. Openers get pushed. On a closer: if the stack is empty or its top isn't the matching opener, return False. Otherwise pop. At the end, leftover openers mean False, so return whether the stack is empty.

Bonus: Sqrt(x)

LeetCode 69, Easy. Statement written from memory.

Given an int x >= 0, return its square root rounded down to an int. You may not use ** 0.5 or math.sqrt.

Examples: 4 gives 2. 8 gives 2 (the real root is 2.83…).

There's no list here, so what's sorted? Think about the numbers 0, 1, 2, … x and what happens to their squares.

Stuck for 8 minutes? Show a hint

Binary search the answer: lo = 0, hi = x. If mid * mid <= x, mid might be the answer, so remember it and try bigger with lo = mid + 1. Otherwise hi = mid - 1. Return the last mid you remembered.
