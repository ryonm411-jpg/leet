For each snippet, pick what you think happens. Then press Run it and see what Python actually does. If it surprises you, change something and run it again.

def best(nums):
    max = 0
    for n in nums:
        max = max(max, n)
    return max

Part 2: read before your first Run

In Lesson 12, two of your three first runs were SyntaxErrors. In the OA every run costs time, and in a live interview you can't run code at all. Before your first Run on each problem below, read your code line by line against this list:

  1. Every ( and [ is closed on the same line.
  2. Every def, if, elif, for and while line ends with :.
  3. No variable is called max, min, sum or id.
  4. There's a return after the loop. Does it still work if the answer comes on the very last item?

Problem 1: Biggest Price Drop

prices[i] is a stock's price on day i. Return the biggest loss you could have made by buying on one day and selling on a later day, as a positive number: the largest prices[i] - prices[j] with i < j. If the price never falls, return 0. len(prices) ≥ 1.

Example: [5, 9, 3, 6, 1, 4] gives 8: buy at 9, sell at 1.

Which approach fits best?

Stuck for 10 minutes? Show a hint

Keep two numbers: high, the highest price so far, and worst, the biggest drop so far. For each later day, compare high - price with worst first, then update high.

Problem 2: Busiest Hour

hours is a non-empty list of whole numbers from 0 to 23, one per order: the hour the order was placed. Return the hour with the most orders. If several hours tie, return the smallest hour.

Example: [14, 9, 14, 9, 20] gives 9. Hours 9 and 14 both have 2, and 9 is smaller.

Which approach fits best?

You count orders per hour in a dict. With n orders, how much extra space does the dict use?

Stuck for 10 minutes? Show a hint

This tie rule is different from Top Seller's. "First seen" doesn't matter here, only the smallest hour. Since the hours are 0 to 23, you can loop for h in range(24) over every hour in order and keep one with a strictly greater count.

Problem 3: Repeat Within k

ids is a list of customer IDs (integers), one per order, in time order, and k ≥ 1. Return True if some customer ordered twice with their two orders at most k positions apart: positions i < j with ids[i] == ids[j] and j - i ≤ k. Otherwise return False.

Example: [4, 1, 2, 4] with k = 3 gives True: customer 4 at positions 0 and 3. With k = 2 it would be False.

Which approach fits best?

Your dict maps each customer ID to its latest position. With n orders, how much extra space can it use?

Stuck for 10 minutes? Show a hint

Store the latest position of each ID, not the first one, and overwrite it every time. The newest earlier copy is always the closest one, so it's the only one worth checking. Check before you store.
