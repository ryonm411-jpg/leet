The problem

Written from the video's transcript. The video shows its examples on screen without reading the grids out, so the examples here are my own, in the same spirit.

You're given a time series of robot positions as a 2D grid of 0s and 1s. Each row is one moment in time, and each 1 is a robot at that column. You're also given num_robots. Return True if the time series is valid: between one row and the next, every robot moves at most one column left or right, or stays put.

Example: rows [0, 1, 1, 0] then [1, 0, 0, 1], with 2 robots, gives True. One robot moved left and one moved right. [1, 0, 0, 0] then [0, 0, 1, 0], with 1 robot, gives False, because the robot moved two columns.

Step 1: your clarifying questions (3 minutes)

Before you look at the answers, write the questions you'd ask the interviewer. Aim for some about the data and some about use cases.

Show the interviewer's answers (from the video)
  • Are all rows the same length? Yes.
  • Can num_robots be negative? No. It's 0 or a positive integer.
  • Minimum size? There's at least one row.
  • Can two robots occupy the same slot, or collide? No.
  • Is every row guaranteed to have num_robots ones? No. The input could be "a bunch of random zeros and ones". You must check every row has exactly num_robots robots, and return False if not.

The last two are the use-case questions. The engineer said they're the ones people skip, and the ones the naive solution gets wrong.

Step 2: spot the naive trap

The video's first, naive idea: for every 1 in a row, check that the row above has a 1 at the same column or one to either side.

With num_robots = 3, which pair of rows does the naive check wrongly call valid?

Step 3: write it, with no running

Start the timer above for the whole round. Write valid_series. Say your plan out loud first, as you would to an interviewer. Then, before your one Run, write a non-happy test in a comment and trace it line by line. Treat Run as the interviewer reading your code: aim for exactly one.

Stuck for 10 minutes? Show a hint

Write a helper that turns a row into the list of robot columns, which come out left to right. Check that each list has length num_robots. Then compare consecutive rows' lists position by position: the k-th robot from the left must stay the k-th from the left, because robots can't pass through each other without sharing a slot. So check abs(prev[k] - cur[k]) <= 1 for every k.

Step 4: complexity, as the interviewer will ask

The grid has R rows and C columns. You build a positions list for each row and compare neighbouring rows. What's the time cost?

Your solution keeps two position lists, each with up to num_robots entries. The video says the optimal version uses less extra space. How much?
