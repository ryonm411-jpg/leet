Warm-up 2: string tools, with no docs

Your invitation says no outside resources, so you need these from memory. Problems 2 and 4 use them.

print("b,b,b c".split())

What does this print?

for c in "Hi, 2!":
    print(c, c.isalpha(), c.lower())

How many lines print True?

The word-building loop for text with punctuation. You'll want it twice today:

word = ""
for c in text.lower() + " ":      # the extra space ends the last word
    if c.isalpha():
        word += c
    else:
        if word:
            ...                       # do something with word
        word = ""

Without the + " ", the last word never reaches the else, so it's silently dropped. A hidden test checks for this.

Problem 1: Find Pair With Given Sum

Past Amazon OA question. Related to LeetCode 1, Two Sum. Wording from the repo, tidied.

Given a list of positive integers nums and an int target, return the indices of two numbers that add up to target - 30.

  • Pick exactly 2 numbers. You can't pick the same element twice.
  • If several pairs work, return the pair that contains the largest number.
  • Return the indices smaller first, as [i, j]. If no pair works, return [-1, -1] (that rule is ours, as the repo doesn't say).

Examples: [1, 10, 25, 35, 60], 90 gives [2, 3], because 25 + 35 = 60 = 90 − 30. [20, 50, 40, 25, 30, 10], 90 gives [1, 5]: both 20 + 40 and 50 + 10 make 60, and 50 is the largest number in either pair.

At index j you have n = nums[j] and you need 60 - n. What should your dict's key be?

Stuck for 8 minutes? Show a hint

It's Two Sum, plus a "best so far" like Lesson 13's. Check first, then store: need = (target - 30) - n. If need in seen, this pair's largest number is max(n, need). Keep the pair only if that beats your best so far. Then seen[n] = j. Checking before storing is what stops [30] from pairing 30 with itself.

Problem 2: Most Common Word

Past Amazon OA question. Same as LeetCode 819, Easy.

Given a paragraph and a list of banned words, return the most frequent word that isn't banned, in lowercase. Words aren't case sensitive, and punctuation (!?',;.) is ignored, even when it's touching a word. The answer is always unique, and at least one word isn't banned. Banned words are already lowercase.

Example: "Bob hit a ball, the hit BALL flew far after it was hit.", ["hit"] gives "ball". "hit" appears 3 times but is banned. "ball" and "BALL" are the same word.

Your count dict is keyed by words from the paragraph. How much space does it use as the paragraph grows?

Stuck for 8 minutes? Show a hint

Make banned_set = set(banned), so each check is fast. Use the word-building loop from Warm-up 2. Where it says "do something with word", count it if it isn't banned: counts[word] = counts.get(word, 0) + 1. At the end, pick the word with the biggest count. One way is max(counts, key=counts.get). Another is a loop with a best variable.

Problem 3: Substrings of Size K with K Distinct Characters

Past Amazon OA question. The k = 3 version is LeetCode 1876, which counts instead of listing. The repo has only the title, so this wording is the commonly reported version.

Given a lowercase string s and an int k, return every different substring of length k in which all k characters are different. Any order is fine. If there are none, return [].

Examples: "abcabc", 3 gives ["abc", "bca", "cab"]. "abc" appears twice but is listed once. "abacab", 3 gives ["bac", "cab"].

OA strategy: the brute force is fine here. For each start, check whether len(set(s[i:i+k])) == k. That's O(n·k), and k is at most 26 for this to ever be true. Bank it first. If you have time, rewrite it as a window with a count dict.

In the window version you keep a count dict of the characters inside the window. s is lowercase letters only. How much space does that dict use as s gets longer?

Stuck for 8 minutes? Show a hint

Brute force: found = set(). Loop for i in range(len(s) - k + 1):, so the last start still has k characters after it. Take part = s[i:i + k]. If len(set(part)) == k, then found.add(part). At the end, return list(found). The set removes repeats for you. When k > len(s), the range is empty, and you return [] with no special case.

Before the bonus: sorting by two things

Problem 4 needs "most mentions first, and alphabetical when tied". sorted takes a key: a function that turns each item into the thing to compare. Return a tuple, and Python compares the first part, then the second part on a tie. A minus sign flips a number to largest first.

lambda w: (-counts[w], w) is a one-line function: given w, return the tuple. Run it and check that alpha comes before zeta.

Bonus, Problem 4: Top K Frequently Mentioned Keywords

Past Amazon OA question. Related to LeetCode 692. Wording from the repo, tidied.

Given an int k, a list of keywords and a list of reviews, return the k keywords mentioned in the most reviews, most first. A keyword counts once per review, however many times that review says it. Matching ignores case, and punctuation isn't part of a word. On a tie, alphabetical order wins. Only keywords mentioned at least once count, so return fewer than k if fewer were mentioned.

Example: k = 2, keywords ["anacell", "cetracular", "betacellular"], reviews:

"Anacell provides the best services in the city"
"betacellular has awesome services"
"Best services provided by anacell, everyone should use anacell"

This gives ["anacell", "betacellular"]. anacell is in 2 reviews (the third review says it twice, but that's still one review), and betacellular is in 1.

Stuck for 10 minutes? Show a hint

Make wanted = set(w.lower() for w in keywords). For each review, collect its words into a set with the word-building loop, so a repeat in one review is counted once. Then for each word in that set that's in wanted, add 1 to its count. At the end, return sorted(counts, key=lambda w: (-counts[w], w))[:k].
