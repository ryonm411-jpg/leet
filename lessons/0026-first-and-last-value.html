First and last value

About 60-75 minutes · Bounds reps, then three problems and a bonus · Your win: at least 3 of your predictions match what your code really does

In Lesson 22 your loops went one past the end (<= len(nums)). In Lesson 24 they stopped one short (range(len(nums) - 1)). Your ideas were right both times. Only the bounds were off. So this lesson drills one habit: for every range and every while, say the first value and the last value before you move on. Then you predict what your code returns on the smallest input, where off-by-ones show up first.

Warm-up 1: say the bounds

Type the first and last value the loop variable takes, as first, last. In every card, nums has 5 items. Don't run anything.

When does - 1 belong? Only in two places:

  • You are naming the last index itself: hi = len(nums) - 1, or the start of a backwards range.
  • The body reads nums[i + 1], so i must stop one early.

Everywhere else, range(len(nums)) already reaches every index. Don't add - 1 by reflex.

Warm-up 2: read it as typed

def total_pairs(nums):
    total = 0
    for i in range(len(nums)):
        total += nums[i] * nums[i + 1]
    return total

What does total_pairs([1, 2, 3]) do?

def running_sums(nums):
    out = [0] * len(nums)
    total = 0
    for i in range(len(nums) - 1):
        total += nums[i]
        out[i] = total
    return out

What does running_sums([2, 2, 2]) return?

With n = 7, what is n - 1 // 2?

def first_upper(word):
    for ch in word:
        if word.isupper():
            return ch
    return ""

What does first_upper("hEllo") return?

How to work each problem

  1. Say the plan out loud in one or two sentences.
  2. Write the code. After each range or while, stop and say its first and last value for the example.
  3. In the prediction box, type what your code returns on the smallest example (one or two items). Trace your code as typed, not your plan.
  4. Then run. If it doesn't match, find the line where your trace and the code split before you run again.

Problem 1: Monotonic Array

LeetCode 896, Easy. New. Statement written from memory, as LeetCode blocks automated reading.

A list is monotonic if it never goes down (each item >= the one before) or never goes up (each item <= the one before). Return True if nums is monotonic, else False. O(n).

Examples: [7] gives True. [1, 2, 2, 3] gives True. [6, 5, 4, 4] gives True. [1, 3, 2] gives False.

Stuck for 6 minutes? Show a hint

Keep two flags, goes_up and goes_down, both starting False. Compare each pair of neighbours. If a pair goes up, set one flag. If it goes down, set the other. At the end it's monotonic unless both are set. Which bound do you need, since you compare i with i + 1?

Problem 2: Squares of a Sorted Array, cold

LeetCode 977, Easy. Spaced retry from a blank editor. You did it in Lesson 18 twice. Both first attempts swapped in place and only ever moved right. Don't look back.

nums is sorted, smallest first, and may hold negatives. Return a new list of each number squared, also sorted smallest first. It must be O(n), so no sorted().

Examples: [-3, 1] gives [1, 9]. [-4, -1, 0, 3, 10] gives [0, 1, 9, 16, 100]. [-7, -3, 2, 3, 11] gives [4, 9, 9, 49, 121].

You fill the answer from the back. The biggest square left is always at one of the two ends. After you write nums[left] ** 2 into the answer, what moves?

Stuck for 8 minutes? Show a hint

out = [0] * len(nums). Put left at index 0, right at the last index, and write at the last index. While left <= right: compare the two squares, put the bigger one at out[write], move that pointer inward, and do write -= 1.

Problem 3: Find Smallest Letter Greater Than Target

LeetCode 744, Easy. New. Statement written from memory. It's the "first True" search from First Bad Version, on a new problem.

letters is a list of lowercase letters sorted smallest first, with at least two different letters, and maybe repeats. Return the smallest letter that is strictly greater than target. If there isn't one, wrap around and return letters[0]. O(log n).

Examples: ["c", "f"], "c" gives "f". ["c", "f", "j"], "a" gives "c". ["c", "f", "j"], "d" gives "f". ["x", "x", "y", "y"], "z" gives "x".

For each letter, ask "is it greater than target?" Down the sorted list, the answers look like False, False, True, True. What are you looking for?

Stuck for 8 minutes? Show a hint

lo, hi = 0, len(letters). Note there's no - 1: hi = len(letters) stands for "no letter is greater". While lo < hi: if letters[mid] > target, then hi = mid (mid might be the answer), else lo = mid + 1. When the loop ends, lo is the first True. If lo == len(letters), return letters[0].

Bonus: Find First and Last Position of Element in Sorted Array

LeetCode 34, Medium. New. Statement written from memory.

nums is sorted smallest first. Return [first, last], the first and last index where target appears, or [-1, -1] if it isn't there. O(log n), so you can't find one copy and then walk outward.

Examples: [1], 1 gives [0, 0]. [5, 7, 7, 8, 8, 10], 8 gives [3, 4]. [5, 7, 7, 8, 8, 10], 6 gives [-1, -1].

Stuck for 10 minutes? Show a hint

Two "first True" searches. The first index is the first i with nums[i] >= target. The first index of something bigger is the first i with nums[i] > target, so the last copy is one before that. Write the search once as a helper and call it twice. Check that first is in range and that nums[first] == target before you trust it.
