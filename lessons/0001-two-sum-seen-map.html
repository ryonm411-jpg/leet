Your first big interview idea is to spend a little memory so you don't have to repeat work. Interviewers often follow a working answer with “can we do better?”, and trying a different data structure is a standard response. The Tech Interview Handbook lists hash maps first among the structures to try.

The problem

Two Sum: given a list nums and an integer target, return the indices of the two numbers that add up to target. Exactly one answer exists, and you can't use the same element twice. The list can hold up to 10,000 numbers.

The obvious approach checks every pair. Make a guess before reading on.

With 10,000 numbers, how many pairs might the obvious approach check?

Ask a better question

Don't ask “which pair works?” Walk through the list once. At each number x, the only partner that can work is target - x. This value is called the complement. So ask: have I already seen the complement?

A Python dict can answer that in one step. Searching a list with in costs O(n), while a dict lookup costs O(1) on average. Rare collisions can make a dict slower, but the average case is what matters in interviews.

Step through nums = [3, 2, 4], target = 6. Predict each result before pressing Next.

At each number x, what question does the algorithm ask?

The order of the two steps matters. If you store x first and then check, what comes back for [3, 2, 4], target 6?

Assuming average-case lookups, what does the seen-map approach cost?

Now write it

Close your notes and write it from the idea alone. The struggle is what makes it stick. The tests accept the two indices in either order and include one large list that catches slow solutions.

Nice work. Now do it once for real, below.

Stuck for 10 minutes? Show one solution 
def two_sum(nums, target):
    seen = {}  # number -> its index
    for i, x in enumerate(nums):
        complement = target - x
        if complement in seen:
            return [seen[complement], i]
        seen[x] = i

If you open this, close it again and rewrite the function from memory.

Do it the interview way

  1. Open Two Sum on LeetCode. Explain the brute force and its cost out loud.
  2. Explain the seen map, then code it while still talking. Interviewers assess communication, problem solving, technical competency and testing.
  3. Trace [3, 3], target 6, by hand before you submit. State the time and space cost.
